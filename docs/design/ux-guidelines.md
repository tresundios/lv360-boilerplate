# UX Guidelines — LàmViệc360
## Interaction Patterns, Accessibility & Quality Standards

---

## 1. Interaction Design Principles

### 1.1 Feedback for Every Action

Every user action must produce **immediate, visible feedback**:

| Action | Feedback |
|--------|---------|
| Button click | Visual depression (scale 0.98) + loading state if async |
| Form submit | Spinner + disabled state while processing |
| Stage move | Confirmation modal → success toast |
| AI generation | Progress indicator → "Generating..." |
| File upload | Progress bar → success/error state |
| Delete/reject | Confirmation dialog → undo toast |

### 1.2 Error Prevention Over Error Correction

- Show validation inline, in real-time (not only on submit)
- Warn before destructive actions (double-confirm for bulk reject)
- Preserve user work — session-cache AI drafts (NFR-003b)
- Make it easy to undo (5-minute undo window for bulk moves — EMP-FR-019b)

### 1.3 Progressive Disclosure

Show only what is needed at each step:
- Onboarding wizard: one step at a time, progress indicator
- Candidate detail: tabs so everything is accessible but not overwhelming
- AI screening: transparency badge + disclaimer before showing results

## 2. Loading States

Every async operation must have a loading state.

### 2.1 Skeleton Loaders (for data fetching)

Use for: job lists, candidate pipeline, dashboard KPIs

```html
<div class="skeleton-container">
  <div class="skeleton skeleton-title" style="width:60%;height:20px"></div>
  <div class="skeleton skeleton-text"  style="width:100%;height:14px;margin-top:8px"></div>
  <div class="skeleton skeleton-text"  style="width:80%;height:14px;margin-top:6px"></div>
</div>
```

### 2.2 Spinner (for action processing)

Use for: form submit, AI generation, file upload

```html
<button class="btn btn-primary" disabled>
  <span class="spinner" aria-label="Loading"></span>
  Generating JD...
</button>
```

### 2.3 AI Progress (for Gemini API calls)

```html
<div class="ai-loading" role="status" aria-live="polite">
  <div class="ai-loading-icon">✦</div>
  <div class="ai-loading-text">Generating your job description...</div>
  <div class="ai-loading-bar">
    <div class="ai-loading-progress"></div>
  </div>
  <div class="ai-loading-note">Usually takes 5–10 seconds (NFR-003)</div>
</div>
```

## 3. Error States

### 3.1 Form Validation

Inline errors appear below the field immediately on blur:

```html
<div class="field-group">
  <label class="field-label" for="company-name">Company Name *</label>
  <input class="field-input field-error" id="company-name"
         aria-describedby="company-name-error" aria-invalid="true">
  <span class="field-error-text" id="company-name-error" role="alert">
    Company name is required.
  </span>
</div>
```

### 3.2 Toast Notifications

**Success toast:**
```html
<div class="toast toast-success" role="alert" aria-live="polite">
  ✓ Job published successfully — <a href="e02-job-list.html">View listing</a>
</div>
```

**Error toast:**
```html
<div class="toast toast-error" role="alert" aria-live="assertive">
  ✕ AI generation failed. Please try again. (1 retry remaining)
</div>
```

**Undo toast (BR-019b):**
```html
<div class="toast toast-warning" role="status">
  8 candidates moved to Rejected.
  <button class="toast-undo" onclick="undoBulkMove()">Undo (4:47)</button>
</div>
```

## 4. Accessibility Requirements (NFR-013)

### 4.1 Skip Navigation

First element on every page:
```html
<a href="#main-content" class="skip-link">Skip to main content</a>
```

```css
.skip-link {
  position: absolute; top: -40px; left: 0;
  background: #2563EB; color: white; padding: 8px 16px;
  text-decoration: none; z-index: 100;
}
.skip-link:focus { top: 0; }
```

### 4.2 Focus Management

- Modals: trap focus inside modal. On close: return focus to trigger element.
- Sidebar navigation: arrow keys navigate items.
- OTP input: auto-advance to next box on digit entry.

### 4.3 ARIA Patterns

**Modal:**
```html
<div role="dialog" aria-modal="true" aria-labelledby="modal-title">
  <h2 id="modal-title">Reject Candidate</h2>
  ...
  <button aria-label="Close dialog">×</button>
</div>
```

**Pipeline stage badges:**
```html
<span class="stage-badge stage-shortlisted" aria-label="Stage: Shortlisted">
  Shortlisted
</span>
```

**AI badge:**
```html
<span class="ai-badge" aria-label="This content was generated by AI and requires your review">
  ✦ AI Generated
</span>
```

**Consent checkbox:**
```html
<input type="checkbox" id="consent" required
       aria-required="true"
       aria-describedby="consent-description consent-error">
```

### 4.4 Colour Contrast Verification

All text must meet WCAG AA:
- Body text (< 18px): **4.5:1 minimum**
- Large text (≥ 18px): **3:1 minimum**
- UI components and state indicators: **3:1 minimum**

Test with: https://webaim.org/resources/contrastchecker/

### 4.5 Touch Targets (Mobile)

All interactive elements: **minimum 44×44px**
```css
.btn { min-height: 44px; min-width: 44px; }
.nav-item { min-height: 44px; padding: 12px 16px; }
.stage-move-dropdown { min-height: 44px; }
```

## 5. Vietnamese Localisation UX

### 5.1 Language Priority

- **Stage 1:** English labels with Vietnamese placeholder text and mock data
- **Stage 2:** Full Vietnamese UI with English language toggle
- All names/companies/addresses must be Vietnamese in mock data

### 5.2 Vietnamese Number / Currency Formatting

```javascript
// VND salary display
function formatVND(amount) {
  return new Intl.NumberFormat('vi-VN', {
    style: 'currency',
    currency: 'VND',
    minimumFractionDigits: 0
  }).format(amount);
  // Result: "25.000.000 ₫"
}

// In salary range display:
// "25.000.000 – 40.000.000 VND/tháng"
// Never: "25M–40M VND" (too abbreviated)
```

### 5.3 Date Formatting (Vietnamese convention)

```javascript
// Vietnamese date format: DD Tháng MM, YYYY
// Example: "15 Tháng 3, 2026"
// NOT: "March 15, 2026"
const months = ['Tháng 1','Tháng 2','Tháng 3','Tháng 4','Tháng 5','Tháng 6',
                'Tháng 7','Tháng 8','Tháng 9','Tháng 10','Tháng 11','Tháng 12'];
```

### 5.4 Phone Number Display

```
Format: +84 912 345 678
Input:  auto-format as user types
Validation: Vietnamese mobile numbers (+84 9xx or +84 3xx etc.)
```

## 6. Mobile-First Implementation Rules

### 6.1 Navigation Pattern

| Width | Navigation |
|-------|-----------|
| < 768px | Bottom tab bar (public portal) OR hamburger → slide-in sidebar (employer) |
| 768px+ | Sidebar visible, top bar |
| 1024px+ | Full sidebar, expanded labels |

### 6.2 Mobile-Specific Patterns

**Pipeline on mobile (EMP-FR-017):**
- Kanban columns collapse to a list with stage filter tabs
- Stage filter: [Applied] [Screening] [Shortlisted] [Interview] ...
- Each tab shows count: "Screening (8)"

**Filters on mobile (p02):**
- Filter button in top bar → opens bottom sheet (50% screen height)
- Bottom sheet has handle to drag to full-screen
- "Apply filters" button at bottom of sheet

**Long forms on mobile:**
- Each section collapsible
- Sticky "Save & Continue" button at bottom
- Auto-scroll to first error on submit attempt
